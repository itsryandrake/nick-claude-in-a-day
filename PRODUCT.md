# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: Vite + React + TypeScript with native CSS, chosen from the explicit request for a lightweight static project with no backend.

## Users

Nick is the primary reader. He is reviewing and acting on the outcomes of a full-day Claude workshop. Ryan is the sender and needs one polished linkable artifact rather than a long meeting document.

## Product Purpose

Turn Friday's workshop into a concise, practical recap that preserves the ideas, explains the technical delivery path, and makes the next actions obvious.

## Positioning

The page joins the workshop outcomes to a truthful interactive architecture map, so ideas and implementation live in one artifact.

## Operating Context

The recap covers Claude artifacts, Wispr Flow, onboarding inside Nick's GIS app, a finance and personal dashboard for Nick and family, reusable Skills, Claude Code subagents, model choices, and the Redbark trial deadline.

## Capabilities and Constraints

- One responsive static page with no backend.
- Interactive architecture nodes reveal concise details.
- GoDaddy DNS points the domain to Vercel; GitHub changes trigger Vercel deployments; Claude Code edits a local checkout and commits to GitHub.
- No publishing, deployment, remote repository, push, or messages.
- Model claims must be grounded in official Anthropic sources.

## Brand Commitments

The artifact is named “Claude in a Day”. It should feel calm, technical, restrained, and personally useful, with Impeccable and Taste Skill craft principles. Avoid generic card grids, gradient text, invented product claims, and irrelevant metrics.

## Evidence on Hand

- Workshop source: https://claudepub.vercel.app/, especially the slide 9 content on reusable Skills, tools and connectors, and model choices.
- Official Anthropic launch pages for Claude Sonnet 5.5 and Claude Haiku 5.5.
- No customer metrics, testimonials, screenshots, or finished product claims were supplied; none may be invented.

## Product Principles

1. Make the next action visible without turning the page into an alert.
2. Show system relationships accurately rather than simplifying them into false connections.
3. Use plain language that Nick can revisit after the workshop.
4. Separate reusable procedures, model choice, and delegated subagents into distinct concepts.
5. Keep human review and judgment explicit.

## Accessibility & Inclusion

Use semantic landmarks, visible focus, keyboard-operable controls, WCAG AA contrast, responsive layout, and a static reduced-motion mode.
